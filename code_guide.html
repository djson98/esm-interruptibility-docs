핵심 코드 5개만 읽기

전체 코드를 다 읽기 전에 아래 다섯 군데를 이해하면 앱의 뼈대가 잡힙니다.

private suspend fun collectResponses(): CollectedSession {
    val answers = mutableListOf<RecordedAnswer>()

    for (question in QUESTIONS) {
        val answer = recordAnswerWithRetry(question)
        answers += answer

        if (!answer.hasValidResponse) {
            return CollectedSession(
                answers = answers,
                outcome = SessionOutcome.NO_RESPONSE,
                noResponseAtQuestion = question.number,
            )
        }

    }

    return CollectedSession(
        answers = answers,
        outcome = SessionOutcome.COMPLETED,
    )
}

읽는 법

  • QUESTIONS에는 Q1, Q2가 들어 있습니다.
  • 답이 없으면 그 자리에서 NO_RESPONSE로 종료합니다.
  • “그만”과 “아니요”도 일반 응답으로 저장합니다. 별도의 음성 중단 질문은 없습니다.
  • 두 질문을 통과하면 COMPLETED입니다.
private suspend fun recordAnswerWithRetry(
    question: Question,
): RecordedAnswer {
    for (attempt in 1..MAX_QUESTION_ATTEMPTS) {
        val answer = recordAnswer(question, attempt)

        if (answer.hasValidResponse ||
            attempt == MAX_QUESTION_ATTEMPTS
        ) {
            return answer
        }

        answer.audioFile.delete()
    }

    error("Question recording attempts were not executed.")
}

읽는 법

  • 질문당 최대 2번 녹음합니다.
  • VAD가 음성을 감지하고 전사 문자열도 있어야 유효 응답입니다.
  • 첫 녹음이 무효면 파일을 지우고 같은 질문을 다시 재생합니다.
  • 두 번째 결과는 성공이든 실패든 호출자에게 반환해 결과를 결정합니다.
suspend fun completeAndScheduleNext(
    deviceId: String,
    scheduleId: String,
): GroupScheduleSyncResult? {
    completeSchedule(deviceId, scheduleId)

    val device = checkNotNull(
        deviceRepository.findDevice(deviceId)
    )
    if (device.role != DeviceRole.LEADER.name) return null

    val startsInSeconds =
        scheduleCalculator.calculateRandomDelaySeconds()

    return createGroupSchedule(
        deviceId = deviceId,
        startsInSeconds = startsInSeconds,
        continuation = true,
    )
}

suspend fun runOnce(deviceId: String): HeartbeatResponse {
    val battery = readBatteryStatus()
    val response = heartbeatClient.send(
        deviceId = deviceId,
        batteryLevel = battery.level,
        isCharging = battery.isCharging,
    )

    deviceRepository.registerDevice(
        deviceId = response.deviceId,
        deviceAlias = response.deviceAlias,
        groupId = response.groupId.orEmpty(),
        role = response.role,
        lastHeartbeatAt = response.lastSeenAt,
        updatedAt = response.lastSeenAt,
    )
    applySchedule(response)
    return response
}

  • 폰의 배터리와 충전 상태를 읽습니다.
  • 서버는 별칭·그룹·역할·다음 스케줄을 응답합니다.
  • 기기 설정을 Room에 반영합니다.
  • applySchedule이 새 일정이면 Room 저장과 AlarmManager 등록을 수행합니다.
override fun onReceive(context: Context, intent: Intent?) {
    if (intent?.action != Intent.ACTION_BOOT_COMPLETED) return

    val pendingResult = goAsync()
    CoroutineScope(SupervisorJob() + Dispatchers.IO).launch {
        try {
            restoreLocalSchedule(context.applicationContext)
        } finally {
            HeartbeatService.start(context.applicationContext)
            pendingResult.finish()
        }
    }
}

// Room에서 미래 스케줄 조회 → AlarmManager에 재등록
// 이미 지난 스케줄이면 로컬에서 제거

읽는 법

  • 폰 부팅 완료 방송만 처리합니다.
  • Receiver 시간이 짧으므로 goAsync() 뒤 IO 코루틴을 사용합니다.
  • 재부팅 때 사라진 AlarmManager 예약을 Room 데이터로 복구합니다.
  • 마지막에는 하트비트 서비스도 다시 시작합니다.

데이터는 어디에 저장되나

폰은 장애에 대비해 원본을 보존하고, 서버는 여러 폰의 결과를 한곳에서 조회합니다.

폰 · Room Database

앱이 오프라인이거나 서버 요청이 실패해도 기기 안에 남는 데이터입니다.

sessionsQ1·Q2 WAV, 전사, 시도, outcome
devices별칭, 그룹, 역할, 다음 일정, 마지막 heartbeat

서버 · SQLite

연구자가 대시보드에서 여러 기기의 상태와 세션을 함께 보는 데이터입니다.

sessions업로드된 세션과 오디오 BLOB
devices관리자 설정, 연결 상태, 일정 상태
group_schedule_controls그룹별 연속 테스트 허용 여부

왜 이 구조는 읽을 수 있나

핵심은 “파일이 많아도 각 파일을 한 문장으로 설명할 수 있다”는 점입니다.

Runner는 순서

SessionRunner는 질문 흐름만 알고 MediaRecorder나 SQL 세부사항은 모릅니다.

Client는 통신

API 엔드포인트마다 클래스가 아니라 기기·세션·스케줄 같은 기능 영역별 클라이언트입니다.

Repository는 데이터 창구

호출자는 Room 쿼리를 몰라도 “세션 저장”, “다음 일정 조회”라고 말할 수 있습니다.

Manager는 연결

서버, Room, AlarmManager처럼 세 개 이상을 이어야 할 때만 조정 클래스를 둡니다.

한 줄 요약: 리더 폰이 다음 간격을 계산해 생성 요청을 보내고, 서버는 같은 일정을 그룹 전체에 배포하며, 각 폰은 실행 결과를 다시 서버로 모읍니다.
ESM Interruptibility · 실제 구현 기준 코드 설명서 · 문서 파일 하나로 실행되며 외부 라이브러리를 사용하지 않습니다.
